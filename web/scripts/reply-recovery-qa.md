# 回复恢复回归验证

将 `reply-recovery-fixture.tsx` 复制到隔离前端工作区的
`pages/reply-recovery-qa.tsx`，构建后启动测试服务并打开该页面。
测试页不请求模型，不应包含在部署产物中。

1. 成功回复应显示“任务已完成”，不显示“等待开始”。
2. 切换为 `idle` 应显示等待；`working` 应显示思考。
3. `failed`、`cancelled`、`incomplete` 和 `legacy` 不应显示等待，
   应分别显示失败、取消、未完成和完成状态未验证。
4. 点击“触发回复渲染异常”，应显示警告、完整原文和“重试显示”；
   原文中的 Markdown 和 HTML 标签应以文字展示。
5. 异常时输入框、历史导航仍可操作。渲染器仍异常时重试应继续显示原文。
6. 点击“修复测试渲染器”，再点“重试显示”，应恢复格式展示。
7. 再次触发异常后点击“切换回复”，应正常展示新回复。
8. 点击“无选项问题”，应显示问题及自定义输入框。输入答案后确认，
   应收到原请求编号与答案，不产生客户端异常。
9. 在无选项问题填入文字后点击“切换问题请求”，确认按钮应重新禁用；
   选择 A 和 B 后应能确认，两题答案分别回传，旧答案不得沿用。

部署前移除隔离工作区的测试路由并重新构建。部署后验证实际问候的
流式完成、历史重载、取消后重发和快速切换会话，并检查控制台异常。
