# 名词解释与共享术语库

ReAct 数据分析会检查影响结果的多义名词、内部简称和不明确指标口径。
系统优先展示共享库中已确认的解释；新对话需要选择，本对话中适用的解释可复用。
含义确认不代表数据字段或计算口径已经完整，缺少数据时仍会询问或说明无法计算。

## 确认与保存

在确认卡片中选择候选或填写自定义解释。可以补充计算口径和别名。
“保存到共享术语库”默认勾选，保存后的解释所有人都可以选择。
取消勾选只用于当前对话。必要确认取消或300秒超时，依赖该名词的任务未完成。
保存失败会明确提示，本次已确认的解释仍可使用。

侧栏“共享术语库”支持查看、新增、修改、另存和删除。
同名词可以有多个口径，优先显示当前数据源的解释。
修改、删除不会改变历史回答中已经保存的解释快照。
没有个人身份隔离或审批：所有访问此服务的人共用、维护同一库。
同一对话已确认的含义不再通过通用提问重新选择。
常见明确指标直接采用常规或用户指定口径，在结果中说明；不因公式未经人工确认就补问。仅对无法消除、会改变结果的实际冲突进行计算口径确认；必要确认取消或超时仍停止相关分析。

## 当前模型理解

没有合适的历史解释时，由当前选择的对话模型提供中文解释候选，并保留必要的外文全称。
需要澄清时，候选标注“当前模型理解，未经资料核验”，用户选择后才保存。明确的常见名词和上下文可确定的口径可自动采用，仅保留对话快照，不将模型判定伪造为用户确认或自动写入共享库。
已有历史解释时，可以选择“让当前模型重新理解”获得其他候选。
模型不能合理解释内部词或生成失败时，转为用户自行解释。
名词识别请求失败时，任务明确标为未完成并提示重试，不继续相关分析。

此流程不调用联网搜索，不需要搜索服务或搜索密钥，不生成虚构来源链接。
如果当前对话模型由 API 提供，名词理解仍使用该模型 API，不等于离线本地推理。
模型提出的含义和公式可能错误，用户确认也不等于已通过外部资料核验。

## 存储与部署

记录存入应用元数据数据库的 `shared_term` 表，不写入 ERP 查询数据库。
SQLite 启动时通过现有模型初始化自动新增表。
当前 Docker 使用持久元数据卷，重启后术语仍可读取。
待回答任务仍为单进程内存状态：重启后重新发起任务，而不是恢复旧确认请求。
共享写入在当前单进程服务中串行去重。

## 验证

后端回归位于 `packages/dbgpt-app/src/dbgpt_app/openapi/api_v1/tests/test_term_*.py`。
前端 `npm test` 包含确认提交的有效会话、保存选择和失败响应检查。
上线验收必须验证：首次确认并保存、重启服务、新对话再次选择，以及取消时不执行分析。

## 何时询问

前置检查沿用当前模型的一次请求，区分明确可用、含义明确但缺数据、未知内部名词、实际口径冲突。只询问后两类，缺数据说明缺数据。
共享库单一适用解释可自动采用；多项解释由上下文确定，无法确定才让用户选择。用户明确要求选择时仍提供选择。
平均销售单价默认总销售金额除以总销售数量，不是各行单价的算术平均。仅因理论上可能有含税、退货等区别不提问；数据或业务资料实际存在竞争口径时才澄清。
执行中的工具复用前置明确项，不重复询问。出现新的实际冲突时，clarify_term 提供 evidence 描述具体数据或业务事实，再单独确认；不修改历史快照。
